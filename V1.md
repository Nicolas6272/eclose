# Éclose — Spécification V1

> Version cible : **1.0.0** — Première version commercialisable  
> Dernière mise à jour : juillet 2026  
> Positionnement : savoir **quoi arroser aujourd’hui** dans son potager.

---

## Vision V1

Éclose V1 aide le jardinier potager à **ne plus se demander quoi arroser** : une home « Aujourd’hui », des cultures perso issues d’un catalogue fruits / légumes / aromates FR, des rappels fiables, et un intervalle d’arrosage **ajusté à la pluie et à la chaleur**.

Produit utile au quotidien pour un potager réel, et commercialisable (compte + abonnement).

### Ce que V1 fait

- Parcourir un **catalogue curaté ~50–80 cultures** potager (légumes, fruits du jardin, aromates) en français
- Ajouter ses cultures (date de plantation + dernier arrosage)
- Voir en un coup d’œil **quoi arroser aujourd’hui** (due / overdue / plus tard)
- Marquer « Arrosé » et replanifier le prochain rappel
- Recevoir des notifications locales au bon moment
- Ajuster l’intervalle selon la **météo** (pluie récente, chaleur) — Premium
- Créer un compte pour sauvegarder / sync multi-appareils — Premium
- Paywall transparent (essai 7j, mensuel, annuel)

### Ce que V1 ne fait PAS (volontairement)

- Parcelles / bacs / carrés (→ V1.1)
- Scan / identification photo par IA
- Diagnostic maladie / ravageurs
- Journal photo
- Calendrier de semis avancé
- Compagnonnage
- Fertilisation / rempotage
- Communauté / partage
- Simulation FAO-56 complète (sol AWC, MAD, Kc journalier)

## Catalogue fruits & légumes

Aucune API unique ne fournit « légumes FR + fréquence d’arrosage prête ». Approche V1 :

### Stratégie de données

1. **Catalogue curaté ~50–80 cultures** potager courantes en France — embarqué dans `assets/crops/crops.json`
2. **Source de base** : [plant-variety-database](https://github.com/bripatch/plant-variety-database) (CC BY 4.0), filtré sur catégories vegetable / fruit / herb
   - Champs réutilisés : `water_requirement` (`low` | `medium` | `high`), soleil, jours à récolte
3. **Curation manuelle FR** : noms français, cultures manquantes typiques (mâche, radis, haricot nain, mesclun, etc.), correction des `water_need`
4. **Pas d’API FAO CROPWAT / CropManage en runtime** — trop lourd / US-centric. On s’en inspire pour les coefficients, pas pour le live

### Schéma `crops.json`

```json
{
  "id": 12,
  "name_fr": "Tomate",
  "scientific_name": "Solanum lycopersicum",
  "category": "legume",
  "water_need": "high",
  "base_interval_days": 2,
  "seedling_factor": 0.5,
  "seedling_days": 21,
  "search_keywords": ["tomate", "tomato", "solanum"],
  "image": "assets/crops/images/tomate.webp"
}
```

| Champ | Type | Rôle |
| --- | --- | --- |
| `id` | int | Identifiant stable catalogue |
| `name_fr` | string | Nom affiché |
| `scientific_name` | string? | Optionnel |
| `category` | enum | `legume` · `fruit` · `aromate` |
| `water_need` | enum | `low` · `medium` · `high` |
| `base_interval_days` | int | Intervalle de base (dérivé de `water_need`) |
| `seedling_factor` | float | Multiplicateur stade jeune (&lt; 1 → plus fréquent) |
| `seedling_days` | int | Durée du stade « jeune » après `planted_at` |
| `search_keywords` | string[] | Index recherche FR/EN |
| `image` | string | Asset local ou URL Storage |

### Mapping `water_need` → `base_interval_days` (valeurs initiales)

| `water_need` | `base_interval_days` | Exemples |
| --- | --- | --- |
| `high` | 2 | Tomate, concombre, courgette, basilic |
| `medium` | 3 | Laitue, haricot, poivron, fraisier |
| `low` | 5 | Ail, oignon, romarin, thym |

Ces valeurs sont des **points de départ calibrables** après usage réel ; l’utilisateur peut overrider par culture.

### Affichage catalogue

Liste / grille simple : **nom FR + besoin en eau** (discret). Recherche instantanée sur `name_fr` + `search_keywords`. Pas besoin d’une grille photo « reconnaissance visuelle » à 1000 entrées.

## Modèle utilisateur — `user_crops`

Seul l’**état propre à l’utilisateur** est persisté. Nom catalogue, image et intervalle de base sont **résolus à la lecture** via `catalog_crop_id` → `crops.json` (sauf override).

| Champ | Type | Description |
| --- | --- | --- |
| `id` | UUID | Identifiant de l’instance |
| `catalog_crop_id` | int | Référence catalogue |
| `custom_name` | string? | Optionnel (« Tomates cerises balcon ») |
| `planted_at` | date | Pour le stade jeune / établi |
| `last_watered_at` | datetime | Dernier arrosage |
| `interval_override_days` | int? | Override manuel de l’intervalle de base |
| `added_at` | datetime | Date d’ajout |
| `user_id` | UUID | Lien Supabase Auth (cloud uniquement) |

Champs **non stockés** (résolus) :

- `name` → `custom_name` ?? `name_fr`
- `base_interval_days` → override ?? catalogue
- `image` → catalogue

### Profil lieu (météo)

| Champ | Type | Description |
| --- | --- | --- |
| `latitude` | float | Pour Open-Meteo |
| `longitude` | float | Pour Open-Meteo |
| `place_label` | string? | Affichage (« Lyon ») |

Demandé **une fois** (onboarding ou Paramètres). Pas de parcelle.

### Stockage — local-first + sync cloud

| Couche | Rôle |
| --- | --- |
| **SQLite** | Source de vérité appareil — notifs offline, « Arrosé » sans réseau |
| **Supabase Postgres** | Backup + sync multi-appareils — RLS `user_id = auth.uid()` |

**Comportement sync V1**

- Écriture locale d’abord, push Supabase en arrière-plan
- À la création de compte : push des cultures locales
- Login nouvel appareil : pull cloud → SQLite
- Conflits : last-write-wins sur `last_watered_at`
- Offline : données locales utilisables, sync au reconnect
- Sync multi-appareils = **Premium**

## Algo d’arrosage V1 — « checkbook lite »

Objectif : **fiable et compréhensible**, pas une simulation agronomique complète.

FAO-56 full (AWC sol + MAD + Kc par stade + bilan journalier) demande trop d’inputs pour un potager loisir en V1. On garde un **intervalle calendaire ajusté**, pas un bilan hydrique en mm.

```
Ajout culture (plantation + dernier arrosage)
        ↓
Intervalle base (catalogue ou override)
        ↓
Ajustement stade (jeune vs établi)
        ↓
Ajustement météo Premium (pluie + chaleur)
        ↓
nextWateringAt  →  liste Aujourd’hui + notifs
        ↑
   Tap « Arrosé »
```

### Facteurs pris en compte

| Facteur | Gratuit | Premium | Comment |
| --- | --- | --- | --- |
| Besoin culture | ✅ | ✅ | `water_need` → `base_interval_days` |
| Override manuel | ✅ | ✅ | `interval_override_days` |
| Stade | ✅ | ✅ | `planted_at` + `seedling_days` |
| Dernier arrosage | ✅ | ✅ | `last_watered_at` |
| Pluie | ❌ | ✅ | Open-Meteo — reporter si pluie suffisante |
| Chaleur | ❌ | ✅ | Open-Meteo — raccourcir si Tmax / ETo élevé |

### Formules V1

```
base = interval_override_days ?? catalog.base_interval_days

age_days = today - planted_at
stage_factor = age_days < catalog.seedling_days
  ? catalog.seedling_factor
  : 1.0

# Gratuit : pas de météo
heat_factor = 1.0
rain_postpone = false

# Premium :
# heat_factor = 0.7 si Tmax_aujourd’hui > 28°C (sinon 1.0)
#               floor à effective_days >= 1
# rain_postpone = true si rain_mm_last_48h >= 10

effective_days = max(1, round(base * stage_factor * heat_factor))
nextWateringAt = last_watered_at + effective_days days

si Premium et rain_postpone :
  nextWateringAt = max(nextWateringAt, startOfTomorrow)
```

### Seuils initiaux (calibrables)

| Paramètre | Valeur V1 | Notes |
| --- | --- | --- |
| `base` high / medium / low | 2 / 3 / 5 jours | Voir mapping catalogue |
| `seedling_factor` défaut | 0.5 | Jeunes plants = 2× plus fréquent |
| `seedling_days` défaut | 21 | Sauf override catalogue |
| Seuil chaleur `Tmax` | 28 °C | → `heat_factor = 0.7` |
| Fenêtre pluie | 48 h | Cumul Open-Meteo |
| Seuil pluie `rain_skip_mm` | 10 mm | Report au lendemain min. |
| Cap intervalle min | 1 jour | Jamais 0 |

### Hors scope algo V1

- Type de sol / AWC / MAD
- Profondeur racinaire
- Volume d’eau en litres
- Kc FAO journalier / ETc complet
- Parcelles et microclimats
- Distinction arrosage goutte-à-goutte vs arrosoir

### Home = Aujourd’hui (cœur produit)

| Section | Contenu |
| --- | --- |
| **À arroser** | `nextWateringAt <= today` (due + overdue), tri overdue d’abord |
| **Plus tard** | Prochains jours (aperçu 7 j) |
| Empty state | « Rien à arroser » — si Premium et pluie récente : « Pluie récente, on reporte » |

Action principale : bouton **Arrosé** → `last_watered_at = now`, recalcule `nextWateringAt`, replanifie notif.

« Arrosé » disponible **tout le temps** (pas seulement le jour J).

## Notifications

| Type | Déclencheur | Contenu exemple |
| --- | --- | --- |
| Arrosage | Matin du jour où des cultures sont due | « 3 cultures à arroser aujourd’hui 💧 » |
| Arrosage (une culture) | Optionnel si une seule due | « Il est temps d’arroser tes tomates » |
| Fin d’essai | J+6 après souscription | « Ton essai se termine demain » |

### Comportement

- Une notif **quotidienne regroupée** le matin (ex. 8h locale) si au moins une culture est due — évite le spam N notifs
- Recalcul après « Arrosé », au boot, et après refresh météo Premium
- Si Premium + pluie → cultures reportées **hors** de la notif du jour
- Gérer permission refusée (app utilisable, message in-app)
- Replanifier au boot (recovery OS kill)

## Météo — Open-Meteo

### Données consommées (Premium)

- `precipitation_sum` sur les 48 dernières heures (ou hourly agrégé)
- `temperature_2m_max` du jour
- Optionnel V1.0+ : `et0_fao_evapotranspiration` si disponible pour affiner `heat_factor`

### Comportement app

- Cache local 6–12 h — pas d’appel à chaque ouverture de liste
- Fallback si offline / erreur : comportement **Gratuit** (pas de facteur météo), UI discrète « Météo indisponible »
- Pas de clé API obligatoire pour le tier gratuit Open-Meteo (respecter leur fair use / attribution)

## Risques & mitigations

| Risque | Mitigation |
| --- | --- |
| Intervalles trop génériques / faux | Override manuel + calibration après usage réel + empty state honnête |
| Météo imprécise (microclimat jardin) | Seuils conservateurs ; pluie = report, pas suppression définitive |
| Catalogue trop US / EN | Curation FR manuelle des ~50–80 cultures prioritaires |
| Paywall « 5 cultures » frustrant | Valeur Premium claire = météo + sync, pas seulement le compteur |
| Notifs non fiables (OS kill) | `flutter_local_notifications` + reschedule au boot + notif regroupée |
| Rejet store (abo / localisation) | RevenueCat + pages légales + justification météo |
